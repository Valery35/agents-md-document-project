# AGENTS.md для документного проекта

Образец файла рабочего контекста для проекта, результат которого комплект
документов, а не код. Рядом свод требований к тексту, на который образец
ссылается, и измеритель, который считает то, что поддаётся счёту. Всё на двух
языках, русском и английском.

[README in English](README.md)

Большинство образцов AGENTS.md и CLAUDE.md описывают код: как собрать, как
прогнать тесты, какого линтера слушаться. Документный проект устроен иначе.
Комплект согласуют две службы заказчика, каждая отдача несёт номер редакции,
норматив цитируется с номером пункта, а вопрос, который разбирали месяц,
записывается, чтобы через полгода его не вернули. Образец держит это
устройство, отраслевое содержание из него снято.

## Кому и для чего

Тому, кто отдаёт заказчику комплект документов и пишет его вместе с агентом,
который читает `AGENTS.md`, `CLAUDE.md` или файл того же рода: состав работ,
частную записку, концепцию, ведомость форм. Образец даёт агенту устройство
такого проекта, а свод даёт измеримое требование к тексту.

Техническому писателю или редактору, которому нужны правила текста, проверяемые
скриптом и оспариваемые человеком. У каждого правила здесь записано основание,
а числа называет инструмент.

Не для проекта с кодом. Обычные образцы `AGENTS.md` подходят к коду лучше, и
здесь нет ничего о сборке и тестах программ. И не руководство по стилю для
принятия как есть. Таблица стоп-слов принадлежит одному автору, и раздел ниже
говорит, что с ней делать.

## Состав

| Файл | Содержание |
|---|---|
| `AGENTS.example.ru.md` | Образец файла рабочего контекста, 30 разделов |
| `AGENTS.example.en.md` | Тот же образец по-английски |
| `RULES.ru.md` | Требования к текстам, русский свод |
| `RULES.en.md` | То же по-английски, заголовок в заголовок |
| `measure.py` | Измеритель, без зависимостей, Python 3.8 и новее |
| `tests/` | Проверки на возврат для измерителя, по одной на запись в `NOTES.ru.md` |
| `NOTES.ru.md` | Что ломалось в измерителе и что с этим сделано |
| `LICENSE` | MIT |

## Что переносится, а что нет

Образец переносится целиком. Порядок сессии, список того, что не делается без
спроса, вопросы до работы, признак готовности до начала работы, редакции
комплекта и журнал решённых вопросов не зависят ни от отрасли, ни от языка.

Свод это форма для заполнения, а не стандарт для принятия. Таблица стоп-слов
личная, она собрана по находкам в текстах одного автора, и слово, которое режет
ему, тебе может быть нейтрально. Переносится механизм. У каждого запрещённого
слова записана замена, потому что запрет без замены применяют вычёркиванием, а
список растёт по находкам, а не по чьему-то чувству языка.

Английский свод не перевод, а переложение. Часть правил стоит на русской
пунктуации и по-английски неверна. Длинное тире и точка с запятой в английском
законны, и запрещать их нечего. На их месте стоит запрет сцепки.

## Как подключить к своему проекту

1. Скопировать `AGENTS.example.ru.md` в свой проект под именем `AGENTS.md`.
2. Подставить содержание своего проекта вместо угловых скобок.
3. Заменить таблицу стоп-слов в `RULES.ru.md` своими находками, графу замены
   сохранить.
4. Заменить раздел «Требования к текстам» в `AGENTS.md` одной строкой со
   ссылкой на `RULES.ru.md`. В образце раздел выписан целиком только потому,
   что образец должен читаться сам по себе.
5. Положить `measure.py` рядом и прогонять тексты перед отдачей.

## Прогон

```
python measure.py RULES.ru.md
python measure.py --band register AGENTS.example.ru.md
python measure.py --lang ru --band letter letter.md
```

Вывод по чистому тексту и по тексту с находками:

```
== RULES.ru.md   [ru, register: ведомости, подписи, перечни]
   предложений      128
   средняя          9.4   норма 8-11
   коротких <=8     65  51 %
   длинных >=19     12  9 %
   подряд коротких  3   предел 3
   длиннее 28       0
   длиннее 34       0   предел
   ? двоеточие внутри предложения: Два правила стоят на самом языке и в англи
   итог: нарушений 0, к просмотру 2

== черновик.md   [ru, register: ведомости, подписи, перечни]
   ...
   ! стоп-слово: «софт» -> программа, пакет
   ! точка с запятой: Раз идёт; два идёт.
   ? имя файла: знаки вне ASCII: акиновчр
   итог: нарушений 2, к просмотру 1
```

Подписи вывода идут на языке текста. Язык определяется по доле кириллицы, ключ
`--lang` задаёт его явно. Ключ `--band` выбирает полосу ритма, по умолчанию
`note`.

| Полоса | Тексты |
|---|---|
| `register` | ведомости, подписи, перечни |
| `note` | состав работ, записка, концепция |
| `letter` | письмо, объявление |

Измеритель считает длину предложений и разброс, ищет стоп-слова, проверяет
пунктуацию по языку и смотрит на имя файла. Нарушение помечается знаком `!`,
место для просмотра глазами знаком `?`. Код возврата 1 при нарушениях, поэтому
измеритель ставится в pre-commit или в шаг CI. Файл
`.github/workflows/check.yml` прогоняет проверки и измеритель на каждый push.

У измерителя своя история поломок. Она записана в `NOTES.ru.md`, и у каждой
записи там есть проверка на возврат в `tests/`.

Нормы длины разведены по языкам. Английская фраза при том же содержании длиннее
русской, поэтому предел один на язык, а не один на оба.

| Язык | Смотреть глазами | Переписать |
|---|---|---|
| Русский | от 28 слов | от 34 слов |
| Английский | от 38 слов | от 45 слов |

## Рекомендации

Брать сначала образец, потом свод. Образец здесь главное, а свод форма, чьё
содержание ты заменишь.

Полосу выбирать по типу документа, а не по комплекту. У ведомости форм и у
концепции ритм разный, и одна полоса на обе проваливает одну из них.

Не переписывать предложение ради измерителя. Знак `?` это место посмотреть, а
предложение, которое читается с придаточным, остаётся как есть. Правило об
обрубках стоит в своде потому, что инструмент с пределом длины их и порождает,
если слушаться его без чтения.

Держать свод в одном файле и ссылаться на него из каждого проекта. Копия
расходится с оригиналом на второй же правке, а вторая правка приходит всегда.

Английский мерить английскими пределами. Русский предел на английской прозе
проваливает текст за то, что он написан по-английски.

Держать репозиторий вне Dropbox, OneDrive и им подобных, либо исключить `.git`
из синхронизации.

## Чего прогон не ловит

Грамотную фразу, из которой выпало слово. Верное по форме и неверное по
существу утверждение. Абзац, отвечающий не на тот вопрос.

Отсюда порядок работы. Сперва прогон, потом сплошное чтение, и без чтения текст
не готов. Прогон сужает место для чтения, а не отменяет его.
